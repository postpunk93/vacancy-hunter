# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Один пользователь — владелец проекта, соискатель на hh.ru (копирайтинг и лонгриды, вайбкодинг и AI-автоматизация, продвижение контента). Ищет удалённую работу из Томска, ведёт поиск из терминала в папке проекта: говорит с Claude обычными словами («давай настроим», «собери свежие», «черновики по 2, 5, 7»), а таблицу вакансий при необходимости открывает в локальном браузере.

Другие соискатели в продукт не входят: чужие профили, аккаунты и многопользовательский режим не поддерживаются.

## Product Purpose

Провести поиск работы на hh.ru от первого разговора до тестового задания целиком в диалоге с Claude: собрать профиль и критерии, собирать и оценивать вакансии, готовить черновики откликов, вести воронку и напоминать о сроках.

Успех продукта — оффер, соответствующий профилю владельца. Скорость сбора, точность оценки и удобство черновиков служат этой цели, а не заменяют её.

## Positioning

Личный профиль `me/profile.md`, собранный из вердиктов владельца по реальным вакансиям, служит единственным промптом оценки; вердикт «подходит / нет» всегда ставит владелец, а отклик он отправляет сам. Соседний продукт с общей базой вакансий не может честно воспроизвести этот механизм: он опирается на накопленные личные решения и локальную базу, а не на ключевые слова или чужую разметку.

## Operating Context

- Владелец открывает Claude Code (или OpenCode) в папке проекта; хук начала разговора печатает `vacancies todo` с напоминаниями: тестовое со сроком, черновик без отклика, отклик без ответа.
- Команды `hunter` и `vacancies` должны быть в PATH: установка через `uv tool install --editable .`; после смены зависимостей — `--reinstall`.
- Всё личное лежит в `me/` (профиль, стратегия, конфиг, резюме, черновики, база `job-hunter.db`, `.env`, логи, выгрузки) и целиком исключено из git.
- Сбор идёт из публичной выдачи hh (zarplata поддержана, но по умолчанию выключена): поисковый API отдаёт 403 анонимным запросам, поэтому данные берутся из встроенного в HTML JSON. Тексты и оценки кешируются в SQLite.
- Проход запускается вручную (`hunter`, `hunter --days 7`); по желанию сводка дополнительно уходит в Telegram (`telegram: true` + `me/.env`).
- Оценку по умолчанию считает модель через OpenCode (`scoring.model`, по умолчанию `opencode/big-pickle`); `scoring.backend: claude` возвращает оценку на Claude.

## Capabilities and Constraints

Подтверждено:

- опрос и профиль: роли с признаками «да» и «нет», красные флаги, поисковые запросы hh, резюме под роль, стратегия;
- сбор карточек из выдачи и полного текста, отсев рекламы и дублей, оценка 1–10 с причиной и флагами;
- пересчёт оценок по уже скачанным текстам без сети (`vacancies rescore`);
- сверка оценки с вердиктами владельца (`vacancies eval`);
- черновики откликов по фактам из резюме, ответы на вопросы работодателя, отметка тестового со сроком;
- воронка (`applied`, `invited`, `rejected`, `skipped`) и напоминания;
- чтение базы через `vacancies sql`, выгрузка xlsx только по просьбе;
- локальная таблица вакансий в браузере (`vacancies ui`).

Ограничения:

- один пользователь; отклик никогда не отправляется автоматически; вердикт ставит только владелец;
- блокировка или капча hh — остановиться, сказать владельцу, не повторять раньше чем через час (код выхода 3);
- вне продукта: диалоговые команды в Telegram, несколько пользователей, inline-кнопки, стоп-слова, чёрный список работодателей, источники кроме hh и zarplata;
- Python ≥ 3.12, SQLite, локальный запуск; личные данные не попадают в публичные файлы;
- язык интерфейса, документации и диалога — русский.

Открытые решения:

- zarplata отдаёт полную выдачу, но это те же вакансии hh с теми же id: после дедупа она новых не приносит, поэтому убрана из источников по умолчанию (`docs/backlog.md`);
- публикация на GitHub как витрины запланирована, но не выполнена; перед публикацией проверяется отсутствие личных данных.

## Brand Commitments

Название продукта — job-hunter (прежнее имя репозитория vacancy-hunter остаётся архивом). Тон — прямой и фактический, без канцелярита и маркетингового шума; документация и сообщения на русском.

## Evidence on Hand

- Реальные цифры из базы владельца за две недели поиска (README): собрано 467 вакансий по 6 ролям; полный текст у 98, карточки у 369; 84 вердикта — 35 «да», 44 «нет», 5 «может быть».
- Сверка оценки с вердиктами (`vacancies eval`): из 79 вакансий с ответом «да» или «нет» совпало 70 (89%) при пороге 5; средняя оценка 7,4 у «да» и 3,0 у «нет».
- Рабочий код и тесты: `hunter/`, `tests/`, фикстуры выдачи в `tests/fixtures/`.
- Реальных отзывов, клиентов, бенчмарков и кейсов вне личного поиска нет; выдумывать их нельзя.

## Product Principles

1. Решение и действие остаются за владельцем: продукт готовит оценку и черновик, но не отправляет отклик и не ставит вердикт.
2. Оценка строится на личных вердиктах и профиле, а не на общих эвристиках; правка профиля пересчитывает оценки без сети.
3. Всё личное локально: `me/` не публикуется, публичные файлы проверяются на утечки.
4. При блокировке источника продукт останавливается и говорит об этом, а не обходит ограничение.
5. Владелец говорит цель обычными словами, Claude выбирает команды; CLI при этом остаётся полностью доступным руками.
