# Vacancy Hunter — дизайн

Дата: 2026-09-01
Статус: утверждён, готов к написанию плана реализации

## Задача

Личный бот проверяет hh.ru и zarplata.ru раз в 30 минут по заданным
запросам и присылает в Телеграм дайджест вакансий, которых не было
в прошлый раз.

Пользователь один — владелец. Настройки правятся руками в `config.yaml`,
диалогового интерфейса и базы подписчиков нет.

## Проверенные факты

Проверено живыми запросами 2026-09-01, до написания дизайна:

| Проверка | Результат |
|---|---|
| `api.hh.ru/vacancies`, `api.zarplata.ru/vacancies` | 403 `forbidden` при любом User-Agent — анонимный доступ к поиску закрыт |
| `api.hh.ru/areas` | 200, справочники открыты без токена |
| `hh.ru/search/vacancy` (HTML) | 200, встроенный JSON в `<template id="HH-Lux-InitialState">`, 50 вакансий на страницу |
| `order_by=publication_time&search_period=1` | Работает, выдача отсортирована по свежести |
| `only_with_salary=true` | Работает на стороне hh |
| `zarplata.ru/vacancies` | Тот же движок и тот же `HH-Lux-InitialState`; объёмы несопоставимы (1 результат против 3651 на hh по запросу «python») |
| Реклама в выдаче | Присутствует, помечена флагом `@isAdv` |

Из этого следуют два решения. Первое: данные берём парсингом публичной
выдачи, а не через API — путь с регистрацией приложения на dev.hh.ru
отклонён. Второе: hh и zarplata обслуживает один парсер, различаются
только базовый домен и путь поиска.

Доступные поля вакансии: `vacancyId`, `name`, `company`, `compensation`
(`from`/`to`/`currencyCode`/`gross`/`mode` либо маркер `noCompensation`),
`area`, `publicationTime`, `workFormats`, `workExperience`,
`links.desktop`, `@isAdv`.

Оба сайта редиректят на региональный поддомен (например `tomsk.hh.ru`).
Параметр `area` при этом применяется корректно, редиректы нужно просто
разрешить в HTTP-клиенте.

## Архитектура

Один проход — один запуск процесса, который завершается. Планировщик
задач Windows запускает его каждые 30 минут. Состояние между запусками
живёт только в SQLite.

### Поток данных

```
config.yaml
   ↓  (запросы × источники)
sources.build_url()   → https://hh.ru/search/vacancy?text=…&order_by=publication_time
   ↓
fetch.get_html()      → HTTP с браузерными заголовками, паузы, ретраи
   ↓
parse.extract()       → HH-Lux-InitialState → list[Vacancy]
   ↓
filters.apply()       → реклама, вакансии без зарплаты, дубли внутри прохода
   ↓
store.unseen()        → отсев уже отправленного (SQLite, ключ source:id)
   ↓
digest.render()       → текст дайджеста
   ↓
telegram.send()       → и только после успеха → store.mark_seen()
```

Порядок двух последних шагов — инвариант проекта. Вакансии помечаются
виденными после подтверждённой отправки, иначе сбой Телеграма молча
съедает партию вакансий навсегда.

### Модули

| Файл | Ответственность | Зависит от |
|---|---|---|
| `models.py` | `Vacancy`, `SearchQuery` (dataclasses) | — |
| `config.py` | `config.yaml` → объекты, валидация | models |
| `sources.py` | Сборка URL поиска для hh и zarplata | models |
| `fetch.py` | HTTP: заголовки, паузы, ретраи | — |
| `parse.py` | HTML → `list[Vacancy]` | models |
| `filters.py` | Локальный отсев | models |
| `store.py` | SQLite: `unseen()`, `mark_seen()`, очистка | — |
| `digest.py` | `list[Vacancy]` → текст сообщений | models |
| `telegram.py` | `sendMessage` | — |
| `run.py` | Оркестрация прохода, логи, коды выхода | все |

Каждый модуль — 30–80 строк. Деление даёт две конкретные выгоды:
`parse.py` тестируется на сохранённом HTML без сети, а `fetch.py`
остаётся единственным местом правок, когда hh начнёт капризничать
с заголовками.

## Конфигурация

`config.yaml` — единственный файл, который правит пользователь:

```yaml
sources: [hh, zarplata]

defaults:              # применяются к запросу, если тот не переопределит
  area: 1              # 1 = Москва, 2 = СПб, 113 = вся Россия
  only_with_salary: true
  search_period: 1     # выдача за сутки — страховка от пропусков
  max_pages: 1         # 50 вакансий на страницу

queries:
  - name: "Python backend"
    text: "python AND (backend OR бэкенд) NOT стажёр"
    salary: 200000
    experience: between3And6
    work_format: remote

  - name: "Data Engineer"
    text: "data engineer"
    area: 113
```

Поле `text` уходит на hh без изменений. hh понимает `AND`, `OR`, `NOT`,
кавычки и префикс `NAME:` для поиска по заголовку — это даёт исключения
без кода на нашей стороне.

Секреты хранятся в `.env` и не попадают в `config.yaml`:
`TG_BOT_TOKEN`, `TG_CHAT_ID`.

## Фильтрация

На стороне hh: `text`, `area`, `salary`, `experience`, `work_format`,
`only_with_salary`, `search_period`, `order_by`.

Локально, после разбора ответа:

1. `@isAdv` — рекламные врезки. Обязательно: в проверке первой строкой
   выдачи шла реклама с датой публикации «сегодня» и датой создания
   декабрь 2024.
2. `noCompensation` — страховка на случай, если hh перестанет уважать
   `only_with_salary`.
3. Дубли внутри прохода — одна вакансия попадает в выдачу по нескольким
   запросам пользователя. Дедупликация применяется к объединённому
   списку всех запросов прохода; вакансия остаётся в первой группе,
   где встретилась, считая от начала списка `queries`.

Стоп-слова и чёрный список работодателей в первую версию не входят.

## Формат сообщения

`parse_mode=HTML`, превью ссылок отключено.

```
🔎 12 новых вакансий · 1 сен, 14:30

Python backend
• Senior Python Developer
  Авито · 350–450 тыс ₽ · Москва, удалённо
• Python-разработчик
  Точка · от 250 тыс ₽ · удалённо

Data Engineer
• Data Engineer (Greenplum)
  Х5 · 300 тыс ₽ на руки · Москва
```

Название вакансии — кликабельная ссылка, поэтому «кто, что, почём»
укладывается в две строки. Группировка по имени запроса из конфига
показывает, какой фильтр сработал.

HTML выбран вместо MarkdownV2 намеренно: в названиях вакансий регулярно
встречаются скобки, точки и дефисы, а MarkdownV2 требует экранировать
полтора десятка символов и падает при малейшей ошибке. Экранируем
`&`, `<`, `>`.

Ограничения:

- Группы идут в том же порядке, что и `queries` в конфиге, вакансии
  внутри группы — от свежих к старым по `publicationTime`.
- Сообщение длиннее 4096 символов режется на несколько по границе групп.
  Если одна группа не влезает целиком, она режется по границе вакансии.
- Если за проход набралось больше 30 вакансий, отправляются первые 30
  в этом же порядке, а в конце добавляется «и ещё N — придут в следующем
  проходе». Остаток не помечается отправленным: `store.unseen()` найдёт
  его в следующий раз и доставит, а не потеряет молча.

## Состояние

```sql
CREATE TABLE seen (
  key           TEXT PRIMARY KEY,  -- "hh:134991226"
  first_seen_at TEXT NOT NULL,
  sent_at       TEXT
);

CREATE TABLE meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

Префикс источника в ключе обязателен: идентификаторы hh и zarplata
принадлежат разным пространствам.

Таблица `meta` хранит служебные отметки времени: `last_sent_at` для
суточного признака жизни и `last_warning_at` для ограничения частоты
предупреждений. Без неё оба правила из раздела об отказах реализовать
негде.

Записи старше 90 дней удаляются на каждом проходе. Вакансия, снятая
и переопубликованная спустя квартал, считается новой, а база не растёт
бесконечно.

### Первый запуск

При пустой базе новыми окажутся все вакансии из выдачи — это стена
текста вместо пользы. Поэтому при пустой базе бот помечает всю текущую
выдачу виденной и отправляет одну строку: «Запущен, слежу за N
запросами, в базу занесено M вакансий. Дальше — только новые».

## Обработка отказов

Один сбойный запрос не роняет проход.

| Ситуация | Поведение |
|---|---|
| Таймаут или 5xx на одном запросе | 3 ретрая с паузами 2с, 5с, 12с; затем запрос пропускается, в дайджест добавляется строка «⚠️ запрос "X" не выполнен». Такое предупреждение не чаще раза в сутки |
| 403 или капча на одном из источников | Ретраев нет. Источник пропускается до конца прохода, предупреждение называет его; результаты остальных источников и запросов доставляются как обычно |
| 403 или капча на всех настроенных источниках | Предупреждение в Телеграм не чаще раза в сутки, выход с кодом 3 |
| Не найден `HH-Lux-InitialState` или карточка вакансии не разбирается (сайт сменил поля) | HTML сохраняется в `debug/`, в Телеграм уходит «парсер сломался» — это предупреждение показывается всегда, суточный cooldown к нему не применяется |
| Телеграм недоступен, включая обрыв соединения на уровне транспорта | `mark_seen` не вызывается, выход с кодом 1 — следующий проход повторит отправку |
| Первый проход не получил ни одной страницы (например, нет сети при входе в систему) | Отметка о первом запуске не ставится, выход с кодом 0 — следующий проход снова считается первым |
| Повреждена или заперта `state.db`, либо иная непредвиденная ошибка | Перехватывается на верхнем уровне, попадает в `logs/hunter.log`, выход с кодом 4 |
| Новых вакансий нет | Сообщений нет |

Четвёртая строка важнее остальных. Главный риск бота — не падение,
а немота: парсер ломается о редизайн, сообщения прекращаются,
и пользователь неделю считает, что вакансий просто нет. Поломка
разбора обязана быть громкой, поэтому в отличие от сетевых предупреждений
у неё нет суточного cooldown — иначе один рядовой таймаут может на сутки
заглушить сообщение о том, что парсер сломался.

По той же причине: если за 24 часа не ушло ни одного сообщения, бот
отправляет строку «за сутки новых нет, всё работает». А поскольку
у процесса под `pythonw.exe` нет stderr, непредвиденное исключение на
верхнем уровне (`main()`) тоже обязано попасть в лог — иначе оно проходит
незамеченным.

Логи пишутся в `logs/hunter.log` с ротацией. Каждый проход фиксирует:
число запросов, получено вакансий, осталось после фильтров, новых,
отправлено.

## Тестирование

Ни один тест не ходит в сеть. Сохранённые страницы hh и zarplata
становятся фикстурами.

- `parse.py` — на фикстурах: из страницы hh извлекается 51 карточка
  (50 вакансий плюс одна рекламная врезка), поля заполнены, врезка
  помечена флагом. Главный тест проекта: он ловит редизайн.
- `filters.py`, `sources.py`, `digest.py` — чистые функции, табличные
  тесты. Для дайджеста отдельно: разбиение по границе 4096 и обрезка
  на 30 вакансиях.
- `store.py` — SQLite в памяти: повторный проход не отдаёт то же самое.
- `config.py` — валидация и понятные сообщения об ошибках.
- `fetch.py`, `telegram.py` — тонкие обёртки, тесты с подменённым HTTP.
- `run.py` — один сквозной тест с подменёнными сетью и Телеграмом.
  Проверяет инвариант: при неудачной отправке `mark_seen` не вызывается.

## Установка

Python 3.14 (проверено на машине). Зависимости: `httpx`, `pyyaml`,
`pytest`. SQLite входит в стандартную библиотеку.

`install_task.ps1` регистрирует задачу в Планировщике: старт при входе
в систему, повтор каждые 30 минут, запуск через `pythonw.exe` — чтобы
не мигало окно консоли.

## Границы первой версии

Не входит: диалоговые команды в Телеграме, несколько пользователей,
inline-кнопки, стоп-слова, чёрный список работодателей, источники
кроме hh и zarplata, разбор полного описания вакансии.
