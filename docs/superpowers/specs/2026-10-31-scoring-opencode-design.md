# Оценка вакансий через OpenCode

## Зачем

Сейчас оценку вакансий делает Claude Code (`claude -p`, подписка владельца).
Переводим исполнителя на OpenCode, начиная с бесплатной модели, но оставляем
Claude как второй бэкенд: сначала прогнать одну пачку обоими и сравнить,
потом решить. Владелец выбрал вариант «переключатель бэкенда» (вариант 1).

## Что хотим

- В `me/config.yaml` появляется `scoring.backend: opencode | claude`,
  по умолчанию `opencode`. Модель задаётся там же в формате OpenCode
  (`opencode/big-pickle`) или Claude (`sonnet`).
- Бэкенд `opencode`: `opencode run --agent vacancy-scorer --model <модель>
  --format json`, JSON-массив вакансий уходит в stdin (проверено по исходнику
  бинаря: `run` читает stdin, если он не TTY; ограничения argv не мешают).
- Системный промпт (правила оценки + `profile.md`) и запрет инструментов —
  в конфиге агента во временной папке на каждый вызов: агент `vacancy-scorer`,
  `system` = текущий `_PROMPT` с профилем, `permissions: deny *`,
  `steps: 1`, `hidden: true`. Так же, как сейчас, системный промпт заменяет
  базовый, и не тратятся лишние токены на промпт OpenCode.
- Ответ: поток JSONL. Склеиваем все `text`-части, вынимаем из них
  JSON-объект (снимаем возможные ```-обёртки), отдаём в `parse_scores`.
  Событие `error` — это ошибка: текст из `error.message`, при `retryAfterMs`
  добавляем «повтор через N ч».
- Ошибка квоты/лимита не повторяется (`ATTEMPTS` не тратится): сразу
  предупреждение «модель не оценила: …».
- Общая ошибка обоих бэкендов называется `ScoringError` (бывший `ClaudeError`),
  интерфейс `Ask(system, payload) -> object` не меняется.
- `vacancies rescore --limit N` — прогнать только N самых свежих вакансий
  с текстом. Без флага поведение прежнее.
- В хеш критериев добавляется бэкенд: старые оценки Claude остаются под своим
  хешем, новые считаются заново.
- Пользовательские тексты: «Claude не оценил» → «модель не оценила»; в
  `GUIDE.md`, `README.md`, `config.example.yaml` — упоминания оценки через
  подписку Claude заменяются на OpenCode (слой сессии — `CLAUDE.md`,
  `.claude/skills/` — не трогаем).

## Чего не делаем

- Не переводим слой сессии (skills, хук, `CLAUDE.md`) на OpenCode —
  это отдельная задача.
- Не подключаем платных провайдеров и не меняем порог/промпт оценки.
- Не чистим историю сессий OpenCode: каждый вызов оставляет сессию, это
  принятая плата за простой CLI.

## Пилот

После сброса бесплатной квоты (провайдер ответил `FreeUsageLimitError`,
повтор через ~4,5 ч):

1. `vacancies rescore --limit 10` — печатает 10 строк «оценка — почему».
2. Владелец смотрит глазами, правдоподобны ли оценки и причины.
3. Дополнительно сверяем с архивом `me/archive/reset-2026-10-31/job-hunter.db`:
   там 86 старых оценок Claude; по совпадающим id видно расхождение.
4. Если качество приемлемо — оставляем `opencode`, иначе меняем модель
   (`model:` в конфиге) или бэкенд (`backend: claude`) и повторяем.

## Риски

- Бесплатная квота общая на все `opencode/*` модели и кончается быстро:
  проход в ~10 пачек может упереться в лимит. Лечится ожиданием или платным
  провайдером — вне этой задачи.
- Качество бесплатной модели на русских вакансиях неизвестно; пилот и есть
  проверка.
- Формат ответа не гарантирован схемой, как у Claude: разбор терпимый
  (битые строки пропускаются), но пустой/неJSON ответ = вакансии без оценки
  с понятной причиной, как сейчас.
