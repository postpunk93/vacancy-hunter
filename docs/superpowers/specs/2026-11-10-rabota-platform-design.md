# rabota.ru — третья площадка

## Что и почему

rabota.ru — площадка с собственным пулом вакансий, в отличие от zarplata,
которая отдаёт те же id, что hh. Проверено вживую 2026-11-10:

| Что | Значение |
|---|---|
| Живых вакансий всего | ~4 600 |
| «менеджер», неделя, Москва (дефолт по IP) | 741 |
| «менеджер», неделя, вся Россия (`all_regions=1`) | 3 520 |
| «менеджер», неделя, вся Россия + удалёнка | 106 |
| «редактор копирайтер удаленно», месяц, удалёнка | 16 |
| «контент-менеджер SMM удаленно», месяц, удалёнка | 15 |

То есть источник рабочий, но небольшой: по контент-ролям он добавляет
порядка 15 вакансий в месяц, зато не пересекается с hh. Удалёнка режет
выдачу примерно в семь раз.

Выдача и страница вакансии — Nuxt-приложение. Полный текст описания есть
**только** в payload `window.__NUXT__`: в разметке `<div itemprop="description">`
пустой, а `ld+json` на странице вакансии нет вовсе (на выдаче — есть,
одним блоком-массивом). Payload — не JSON, а JS-литерал в function-режиме:
`(function(a,b,…){ …; return {…} }(аргументы));`, где тело после `return`
ссылается на параметры по имени.

Фильтры, проверенные запросами: `all_regions=1` — вся Россия, `period` до
30 дней (`day`, `three-days`, `week`, `month`), `schedule_ids=6` — удалённая
работа, `min_salary`, `page` (1-based, 30 карточек). `only_with_salary`
сайт молча игнорирует. Синтаксис hh (`NAME:`, `NOT`) не работает: только
обычные слова, поиск нечёткий («редактор» — 6 вакансий за всё время,
«редактор удаленно» — 9).

## Как

### Разбор payload — `hunter/platforms/nuxt.py`

Отдельный модуль, потому что формат чужой площадке и пригодится, если
появится ещё один Nuxt-сайт.

`parse_nuxt(page_html: str, marker: str = "window.__NUXT__=") -> dict`:

1. Найти маркер, взять текст до ближайшего `</script>`.
2. Разобрать заголовок `(function(a,b,…){`, список параметров, тело и
   аргументы вызова (закрывающие `))` в конце).
3. Аргументы разобрать тем же парсером значений и связать с параметрами
   по позиции.
4. В теле перебрать вхождения `return ` **с конца**: первое, после которого
   разобранное значение доходит до конца тела (остались только пробелы и
   `}`), и есть ответ. Так «return» внутри текста вакансии не ломает разбор.
5. Синтаксис значений: объекты с неквотированными ключами, массивы, строки
   в одинарных и двойных кавычках с `\uXXXX`, числа (в том числе дробные
   и отрицательные), `true`, `false`, `null`, `void 0`, `!0`/`!1`, унарный
   минус, одиночный идентификатор — подстановка значения параметра
   (неизвестный идентификатор — `None`).

Маркера нет — `ParseError` (или `Captcha`, решает площадка: модуль только
разбирает). Не разобралось — `ParseError` с позицией и куском текста, чтобы
при смене формата было видно, где сломалось.

### Площадка — `hunter/platforms/rabota.py`

Класс `Rabota`, `name = "rabota"`, `page_size = 30`, `max_pages = 20`.
Карточки и текст берутся из состояния страницы — как у superjob.

`search_url(query, page)`:

```
https://www.rabota.ru/vacancy/?query=<text>&all_regions=1&period=<период>
  [&schedule_ids=6] [&min_salary=<salary>] [&page=<page+1>]
```

Порядок выдачи — релевантность (умолчание сайта), как у superjob.

`search_period(days)`: ближайший период не короче запрошенного из
`(1, 3, 7, 30)`; строка периода — `day`, `three-days`, `week`, `month`.
Возвращаются дни, чтобы `run.py` сам отсекал лишние (он это уже делает,
когда `search_period` не равен запрошенному).

`parse_cards`: `state.rabota.search`; `totalVacancies == 0` — законная
пустая выдача (`[]`); нет `search` — `ParseError`. Карточка → `card_row`,
все колонки таблицы `vacancies`, как у остальных площадок.

| Поле | Откуда |
|---|---|
| `source`, `external_id` | `"rabota"`, `str(id)` |
| `name`, `company`, `company_id` | `title`, `company.name`, `company.id` |
| `url` | `https://www.rabota.ru/vacancy/<id>/` |
| `area` | `places[0].region.name`, иначе `places[0].name` |
| `published_at` | `publish_start_at` (`2026-11-08T15:43:19+03:00`) |
| `salary_from`, `salary_to` | `salary.from`, `salary.to`; `0` — границы нет |
| `currency`, `salary_mode` | из `salary.currency`: строка вида `руб./мес.` → `RUR`, `MONTH` |
| `gross` | `salary.pay_type`: `gross` → `1`, `net` → `0`, пусто → `None` |
| `work_formats` | `[]`: в карточке формата работы нет |
| `salary_frequency`, `experience`, `employment_form` | `None` |
| `card_json` | карточка целиком, как есть |

`salary.currency` — не код, а подпись: в 90 карточках выборки встретилось
только `руб./мес.` (и пусто в четырёх). Поэтому разбор по частям: до слеша —
валюта (`руб.` → `RUR`, `$`/`USD` → `USD`, `€`/`EUR` → `EUR`), после слеша —
период (`мес.` → `MONTH`, `час` → `HOUR`, `день` → `DAY`, `нед.` → `WEEK`).
Неизвестная часть — `None`: лучше пусто, чем почасовую ставку показать
месячным окладом. `pay_type` — это не период, а налоги: `gross`/`net`,
поэтому он идёт в `gross`, а не в `salary_mode`. Частоту выплат rabota
не различает — `salary_frequency` остаётся `None`.

`is_ad = False` всегда: `is_promoted` — платное продвижение вакансии,
а не реклама, и `drop_ads` не должен её выкидывать.

`parse_detail`: `state.rabota.vacancy.vacancy` (+`vacancyCache`, если
основного узла нет). Описание — `html_to_markdown(description)`,
`key_skills` — имена из `skills`, `status` — `active` при `status ==
"published"`, иначе `archived`. `work_formats` — `("REMOTE",)` при
`operating_schedule.id == 6` (в карточке этого нет, поэтому в дайджесте
у rabota формата не будет).

### Формат работы доезжает до базы

`Corpus.update_detail` сейчас пишет только текст, навыки и статус, поэтому
`work_formats` из `Detail.row` теряется: вакансия, найденная проходом,
навсегда остаётся с пустым форматом, даже когда страница скачана. Это
касается не только rabota — у superjob формат тоже известен со страницы
вакансии. Меняем одно место: `update_detail` добавляет к `UPDATE`
`work_formats` **только если деталь его знает** (список непустой), чтобы
не затирать тем, чего страница не сообщила.

`parse_ref`: `/vacancy/<цифры>/` на `rabota.ru` и любом поддомене → id;
префиксная форма `rabota:<id>` приходит через `hunter/platforms/__init__.py`.

`unsupported(query)` — что площадка проигнорирует, чтобы владелец не
думал, что фильтр применился:

- `area`, если не 113: регионы у rabota свои (Москва — 3), `all_regions=1`
  умеет только «вся Россия»;
- `only_with_salary` — параметр игнорируется;
- `experience` — коды опыта свои (0–5), сопоставление с hh-кодами неточное,
  поэтому не фильтруем вовсе;
- `work_format`, если не `remote`.

Зарплата (`min_salary`) и период поддерживаются.

Капча: нет маркера `window.__NUXT__` и в странице есть слова-маркеры
(`captcha`, `капча`, `робот`, `подтвердите`) — `Captcha`; иначе
`ParseError`. `parse_detail` различает так же.

### Капча не должна ронять проход

`hunter/run.py` ловит от площадки только `Blocked`, `FetchError` и
`ParseError`. `Captcha`, который бросают `parse_cards`/`parse_detail`,
уходит в общий `except Exception` — проход падает с кодом 4 и «непредвиденной
ошибкой» вместо обещанного кода 3 и предупреждения. У superjob эта дыра
уже есть, rabota её просто сделает заметнее. Поэтому `_collect` ловит
`Captcha` так же, как `Blocked`: источник считается заблокированным,
в сводку идёт предупреждение, листание по нему прекращается.

### Реестр, конфиг, справочник

- `hunter/platforms/__init__.py`: `rabota` в `PLATFORMS`, докстринг.
- `config.example.yaml`: `rabota` в комментарии к `sources`.
- `me/config.yaml` (личный, в git не идёт): `sources: [hh, superjob, rabota]`
  и `text_by_source.rabota` с обычными словами для каждого из восьми
  запросов — hh-синтаксис площадке не годится. Строки superjob сохраняются:
  карта запроса перекрывает умолчания целиком.
- `hunter/corpus/GUIDE.md`: `--source`, форма ref, `source` в таблице схемы,
  `published_at` и `salary_frequency`.

### Тесты

`tests/test_platforms_nuxt.py` — на синтетических payload: ссылки на
параметры, вложенные объекты и массивы, `\uXXXX`, `void 0`, `!0`,
унарный минус, слово «return» внутри строки, битый payload → `ParseError`.

`tests/test_platforms_rabota.py` — URL (вся Россия, период, удалёнка,
зарплата, пагинация 1-based), карточки из фикстуры, пустая выдача,
страница вакансии (описание, навыки, статус, удалёнка), `parse_ref`,
`unsupported`, капча.

`tests/test_run.py` — `Captcha` от `parse_cards` больше не валит проход:
источник попадает в заблокированные, сводка содержит предупреждение,
код выхода 3.

`tests/test_corpus_store.py` — `update_detail` записывает `work_formats`,
когда деталь их знает, и не затирает пустым списком.

Фикстуры: `tests/fixtures/rabota_search_editor.html` (выдача «редактор»,
удалёнка, неделя), `rabota_search_empty.html`, `rabota_vacancy.html` —
полные страницы, как сняты.

## Не-цели

- Не используем API `/api-web/`: он работает только POST-ом, а разбор
  SSR-страницы даёт то же самое.
- Не поддерживаем регион, отличный от «вся Россия»: id регионов у площадки
  свои, в конфиге `area: 113`.
- Не фильтруем по опыту (сопоставление кодов неточное).
- Не трогаем дедуп, оценку, дайджест, схему базы и zarplata. В `store.py`
  меняется одна строка `update_detail` — ради формата работы, как описано
  выше.
- Не боремся за полный обход пагинации: `max_pages` ограничен, на неполной
  странице листание прекращается само.

## Проверка

- `uv run pytest` — зелёный.
- Живой проход без записи в базу и без оценки:
  `hunter --days 7 --dry-run --no-score` — код выхода 0, rabota даёт
  карточки, предупреждений о смене формата нет.
- `vacancies collect --source rabota --query "редактор копирайтер" --days 7`
  пишет карточки в базу, `vacancies show` показывает описание и навыки.
