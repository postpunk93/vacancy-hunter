# Корпус вакансий для анализа в сессии Claude Code — дизайн

Дата: 2026-10-02
Статус: на ревью у владельца

## Задача

Владелец ищет работу и хочет в обычной сессии Claude Code (в отдельной
папке поиска работы, не в репозитории бота):

1. собрать вакансии по нескольким целевым ролям;
2. отобрать подходящие лично ему — с опорой на рассказ о себе и на
   примеры вакансий, которые нравятся и не нравятся;
3. написать резюме под каждую роль;
4. составить стратегию поиска работы.

Для этого нужен **корпус вакансий** с метаданными и — выборочно —
полным текстом, к которому сессия Claude может обращаться командами и SQL.

### Что есть сейчас

- `state.db` бота хранит только ключ `source:id`, `first_seen_at`,
  `sent_at`. Название, компания, зарплата живут только в памяти прохода
  и уходят в дайджест. Через 90 дней `purge_older_than` стирает и ключи.
- Карточка в выдаче (`HH-Lux-InitialState` →
  `vacancySearchResult.vacancies[]`) содержит ~60 полей, из которых
  `parse.py` берёт 15. Полезные для анализа, но не сохраняемые:
  `company.@trusted`, `company.@category`, `compensation.frequency`,
  `employmentForm`, `responsesCount`, `vacancyProperties` (включая
  `HH_ANTIFRAUD_SUSPICIOUS_VACANCY` с `antifraudPessimizePower`).
- Текст требований в выдаче hh анонимному пользователю не отдаётся:
  `enableVacancySnippets=False`, поле `snippet` отсутствует (проверено
  вживую 2026-10-02, 0 из 50). На zarplata сниппет есть (~700 символов),
  но выдача zarplata вживую — 1 карточка на запрос против 50 у hh.
- Полный текст — на странице `hh.ru/vacancy/<id>`, в
  `vacancyView.vacancyFull.vacancy`: `description` (HTML, в примере
  ~4 тыс. символов текста), `keySkills` (список строк), `status`.
  Страница весит ~700 КБ.
- id вакансий zarplata совпадают с id hh: карточка zarplata ссылается на
  `m.hh.ru/vacancy/<тот же id>`. Это кросспостинг hh.

### Цикл работы, под который делается инструмент

1. Владелец рассказывает о себе → `profile.md`.
2. Присылает 5–10 ссылок на понравившиеся вакансии и 3–5 «похоже, но
   нет» → они загружаются с полным текстом и получают вердикт.
3. Claude собирает портрет: роли, признаки «да»/«нет», поисковые запросы
   под каждую роль → `portrait.md`.
4. По запросам ролей собирается корпус (`vacancies collect`).
5. Claude отбирает кандидатов по метаданным, докачивает полный текст
   выборки, показывает владельцу с обоснованием; владелец ставит
   вердикты; портрет уточняется. 2–3 итерации.
6. По уточнённому портрету — резюме под каждую роль и стратегия.

Код отвечает только за шаги «собрать», «докачать», «хранить», «показать»,
«записать вердикт». Оценка, портрет, резюме и стратегия — работа Claude
в сессии, не программы.

## Структура и границы

```
~/projects/personal/vacancy-hunter/     код (этот репозиторий)
  hunter/            бот — не меняется
  hunter/corpus/     новое: сбор, докачка, хранилище, CLI, GUIDE.md

<папка поиска работы>/                  данные и сессия Claude
  CLAUDE.md          импортирует GUIDE.md + личные договорённости
  vacancies.db       корпус
  profile.md, portrait.md, resumes/<роль>.md, strategy.md
```

- **Точка входа.** В `pyproject.toml` добавляется
  `[project.scripts] vacancies = "hunter.corpus.cli:main"`. Установка один
  раз: `uv tool install --editable ~/projects/personal/vacancy-hunter`.
  Правки кода подхватываются без переустановки.
- **База по умолчанию** — `./vacancies.db` в текущей папке; переопределяется
  глобальным `--db PATH`.
- **Граница с ботом.** Корпус не читает и не пишет `state.db`, не трогает
  дайджест и Телеграм. Переиспользуются: `fetch.get_html`, `fetch.new_client`,
  `sources.build_url`, `models.SearchQuery`, `parse.extract_state`,
  `parse.ParseError`.
- **Единственное изменение общего кода:** в `hunter/fetch.py` появляется
  `NotFound(FetchError)` для HTTP 404 (сейчас 404 — безликий `FetchError`
  с текстом). Подкласс — бот, ловящий `FetchError`, ведёт себя как прежде.
- **Ключ вакансии** — целочисленный id hh без префикса источника. Дубли
  hh/zarplata схлопываются автоматически.
- **`collect` ищет только на hh.** Полный текст всегда со страницы
  `https://hh.ru/vacancy/<id>`.

## Схема базы (`PRAGMA user_version = 1`)

```sql
CREATE TABLE vacancies (
  id                INTEGER PRIMARY KEY,   -- id hh (у zarplata тот же)
  name              TEXT NOT NULL,
  company           TEXT NOT NULL,
  company_id        INTEGER,
  url               TEXT NOT NULL,         -- всегда https://hh.ru/vacancy/<id>
  area              TEXT,
  published_at      TEXT,                  -- ISO 8601
  salary_from       INTEGER,
  salary_to         INTEGER,
  currency          TEXT,
  gross             INTEGER,               -- 0/1/NULL
  salary_frequency  TEXT,                  -- MONTHLY, PER_PROJECT, …
  experience        TEXT,                  -- noExperience | between1And3 | between3And6 | moreThan6
  work_formats      TEXT,                  -- JSON-массив, напр. ["REMOTE","HYBRID"]
  employment_form   TEXT,                  -- FULL | PART | PROJECT | …
  employer_trusted  INTEGER,               -- company.@trusted, 0/1/NULL
  employer_category TEXT,                  -- COMPANY | PRIVATE_INDIVIDUAL | AGENCY | …
  antifraud_power   REAL,                  -- NULL, если нет HH_ANTIFRAUD_SUSPICIOUS_VACANCY
  responses_count   INTEGER,               -- снимок на момент последнего сбора
  description       TEXT,                  -- Markdown из HTML страницы вакансии
  key_skills        TEXT,                  -- JSON-массив строк
  status            TEXT,                  -- статус со страницы вакансии; 'deleted' при 404
  detail_fetched_at TEXT,
  card_json         TEXT,                  -- сырая карточка из выдачи (NULL, если добавлена по ссылке)
  detail_json       TEXT,                  -- сырой vacancyFull.vacancy
  first_seen_at     TEXT NOT NULL,
  last_seen_at      TEXT NOT NULL
);

CREATE TABLE hits (
  vacancy_id     INTEGER NOT NULL REFERENCES vacancies(id),
  role           TEXT NOT NULL,
  query          TEXT NOT NULL,           -- текст запроса или 'manual'
  first_found_at TEXT NOT NULL,
  PRIMARY KEY (vacancy_id, role, query)
);

CREATE TABLE verdicts (
  vacancy_id INTEGER PRIMARY KEY REFERENCES vacancies(id),
  verdict    TEXT NOT NULL CHECK (verdict IN ('yes','no','maybe')),
  note       TEXT,
  updated_at TEXT NOT NULL
);
```

Правила:

- **Поля извлекаются при записи, сырой JSON сохраняется тоже.** Поле,
  которое понадобится позже, достаётся `json_extract(card_json, …)` без
  пересбора.
- **Роль — метка поиска (`hits`), не свойство вакансии.** Одна вакансия
  может найтись под несколькими ролями.
- **Вердикт один на вакансию, без истории.** «Подходит ли мне» не зависит
  от роли.
- **Upsert из выдачи** обновляет поля карточки, `card_json`,
  `responses_count`, `last_seen_at`; не трогает `description`,
  `key_skills`, `status`, `detail_*`, `first_seen_at`, вердикт.
- **Запись со страницы вакансии** заполняет `description`, `key_skills`,
  `status`, `detail_json`, `detail_fetched_at`. Если строки ещё нет,
  создаёт её по данным страницы (общие поля извлекаются из
  `vacancyFull.vacancy`; `card_json` = NULL, `responses_count` = NULL).
- **HTML → Markdown** — стандартный `html.parser`: абзацы, переносы,
  маркированные и нумерованные списки, жирный/курсив; прочие теги —
  в текст; HTML-сущности раскодируются; лишние пустые строки схлопываются.
- **Миграции** — по `PRAGMA user_version`: при открытии базы с версией
  меньше текущей применяются шаги по порядку; база новее кода — ошибка
  с понятным сообщением.

## Команды

Все подкоманды принимают глобальный `--db PATH`.

### `vacancies init`

Создаёт в текущей папке `vacancies.db` (пустая схема) и заготовку
`CLAUDE.md`:

```markdown
@~/projects/personal/vacancy-hunter/hunter/corpus/GUIDE.md

## Обо мне и договорённости
```

Путь в импорте вычисляется из фактического расположения пакета.
Существующие файлы никогда не перезаписываются — о каждом пропущенном
выводится строка.

### `vacancies collect --role R --text T [опции]`

Опции: `--area` (по умолчанию 113), `--days` (по умолчанию 30, максимум
hh), `--pages` (по умолчанию 5), `--salary N`, `--experience V`
(повторяемая), `--work-format F`, `--with-salary`, `--delay` (по умолчанию 2).

- Строит `SearchQuery` и URL через `build_url("hh", …)`.
- Листает страницы до `--pages`, до первой страницы с менее чем 50
  карточками или до пустой.
- Каждую карточку — upsert в `vacancies`, связь — в `hits`.
- Рекламные дубли (`@isAdv`) записываются как обычные — ключ всё равно
  по id.
- Итог: `<роль>: N карточек, новых X, уже были Y`.

### `vacancies fetch ID|URL [ID|URL …] [--role R] [--refresh] [--delay S]`

- Аргументы — id или ссылки hh/zarplata любого поддомена
  (`…/vacancy/<id>`), из ссылки берётся id; нераспознанный аргумент —
  ошибка до любых запросов.
- Уже скачанные (`detail_fetched_at IS NOT NULL` или `status='deleted'`)
  пропускаются без `--refresh`.
- `--role` пишет `hits(role, query='manual')`.
- Итог: скачано / пропущено / не найдено / ошибки (со списком id).

Выборку для докачки делает Claude через SQL и передаёт список id —
отдельной логики выбора в коде нет.

### `vacancies mark ID yes|no|maybe ["комментарий"]`

Пишет или перезаписывает вердикт. Вакансии нет в базе — ошибка с
подсказкой сначала выполнить `fetch`.

### `vacancies show ID [ID …]`

Печатает каждую вакансию Markdown-блоком: название, компания, ссылка,
город, вилка (с частотой выплат и gross/net), опыт, формат, занятость,
отклики, сигналы (непроверенный работодатель, физлицо, антифрод), роли из
`hits`, вердикт с комментарием, навыки, описание. Нет полного текста —
так и написано, с подсказкой `fetch`.

### `vacancies sql "SELECT …" [--json]`

Произвольный запрос к базе, открытой **только на чтение**
(`file:…?mode=ro`, URI-режим). Вывод — таблица с обрезкой длинных ячеек;
`--json` — полный вывод списком объектов. Ошибка SQL — сообщение и
ненулевой код.

## Вежливость и ошибки

- Пауза между HTTP-запросами — `--delay` секунд со случайным разбросом
  ±50%.
- **403 (`Blocked`) или капча** (ответ 200 без `HH-Lux-InitialState`,
  т. е. `ParseError` из `extract_state`) — немедленная остановка команды:
  сообщение, сколько сделано, код выхода 3. Повторов нет.
- **Сеть/5xx** после ретраев `get_html` — в `fetch` вакансия пропускается,
  работа продолжается, в итоге список неудач и код 1; в `collect` —
  остановка этого сбора (страницы последовательны), код 1, уже записанное
  сохранено.
- **404 (`NotFound`)** в `fetch` — строка (если есть) получает
  `status='deleted'`; если строки нет — только сообщение в итоге.
- **Карточка или страница вакансии не разобралась** (структура
  изменилась) — громкая ошибка с id и кодом 1; тихих пустых результатов нет.
- **Прогресс не теряется:** коммит после каждой страницы выдачи и каждой
  вакансии; повторный запуск продолжает с места остановки.

Коды выхода: 0 — успех; 1 — частичная неудача или ошибка разбора;
2 — неверные аргументы; 3 — блокировка/капча.

## Инструкция для сессии: `hunter/corpus/GUIDE.md`

Живёт рядом с кодом, подключается в `CLAUDE.md` папки поиска работы
`@`-импортом — копий нет, при editable-установке всегда совпадает с кодом.

Содержит:

- все команды с примерами вызова;
- схему с пояснением неочевидных полей (`antifraud_power`, значения
  `experience`/`work_formats`, `responses_count` как снимок);
- готовые запросы: кандидаты без вердикта с полным текстом; частота
  навыков по роли через `json_each(key_skills)`; вилки по роли;
  вакансии, найденные под несколькими ролями;
- правила для Claude: докачивать полный текст выборками до ~40 за раз,
  а не всё подряд; при коде 3 остановиться и сообщить владельцу, не
  повторять; вердикты ставит владелец — Claude предлагает и вызывает
  `mark` только после явного ответа;
- цикл работы (см. выше) и соглашение о файлах: `profile.md`,
  `portrait.md` (с командами `collect` для повторяемости),
  `resumes/<роль>.md`, `strategy.md`.

## Тестирование

Загрузка страниц передаётся функцией (как `fetch_page` в `run_pass`) —
сеть в тестах не нужна.

- Новая фикстура страницы вакансии, урезанная до `<template
  id="HH-Lux-InitialState">` (полная страница ~700 КБ).
- Разбор карточки выдачи в строку `vacancies` (включая антифрод,
  категорию работодателя, частоту выплат, отсутствие зарплаты).
- Разбор страницы вакансии → описание, навыки, статус; создание строки
  по странице, если её нет.
- HTML → Markdown: списки, абзацы, сущности, вложенные теги.
- Upsert: повторный `collect` не стирает описание, вердикт,
  `first_seen_at`; обновляет `responses_count` и `last_seen_at`.
- `collect`: остановка пагинации на неполной/пустой странице и по
  `--pages`; запись `hits`.
- `fetch`: пропуск уже скачанных, `--refresh`, 404 → `deleted`,
  ошибка одной вакансии не останавливает остальные, 403 и капча
  останавливают всё с кодом 3.
- Разбор id из ссылок hh/zarplata разных поддоменов и отказ на мусоре.
- `sql`: запись (`INSERT`/`UPDATE`/`DELETE`) отклоняется.
- `init`: не перезаписывает существующие файлы.
- Миграции: новая база получает `user_version=1`; база новее кода —
  ошибка.
- Синхронизация гайда: каждая подкоманда CLI и каждая колонка схемы
  упомянуты в `GUIDE.md`.

## Вне рамок

- Фоновое накопление карточек ботом в корпус — отдельная задача позже.
- Поиск по zarplata в `collect` (те же вакансии hh, выдача — 1 карточка).
- Аномалия «zarplata отдаёт 1 карточку» в самом боте — занести в
  `docs/backlog.md` отдельным пунктом.
- MCP-сервер; генерация резюме, оценка «подходит/нет» и выбор выборки в
  коде — это работа Claude в сессии.
- Любые изменения поведения бота и `state.db` (кроме подкласса
  `NotFound`, совместимого с текущей обработкой).
