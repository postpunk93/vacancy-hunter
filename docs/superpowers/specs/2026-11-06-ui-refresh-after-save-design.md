# Обновление списка после сохранения в таблице

## Что и почему

Рабочий цикл в `vacancies ui`: отправил отклик → поменял этап в строке →
«Сохранить» → нажал «Показать», чтобы список пересобрался по текущим фильтрам.
Без этого строка со старым этапом остаётся на месте, хотя фильтр по этапу её
уже не пропускает, и непонятно, применилось ли изменение. Нужно, чтобы после
сохранения список сам перечитывался, если этап изменился.

## Как

Выбран вариант А: после сохранения — обычный переход на тот же список.

- Форма строки получает `data-status` с этапом на момент рендера.
- На submit JS сравнивает текущее значение селекта этапа с `data-status`.
- Этап изменился и `/save` ответил успешно → `location.href = back + "#v-<id>"`,
  где `back` — скрытое поле формы с текущими фильтрами. Браузер перезагружает
  страницу, список собирается заново с теми же фильтрами, строка подсвечивается
  якорем (или исчезает, если фильтр её больше не пропускает).
- Поменялась только заметка → прежнее поведение: зелёная подсветка и
  «сохранено» на 2 секунды, без перезагрузки.
- Без JS всё как сейчас: сервер отвечает 303 на `back#v-<id>`.

Сервер не меняется: `/save` по-прежнему пишет через `Corpus.set_status` и
отвечает 204 на fetch.

## Не-цели

- Не обновляем строку на месте и не убираем её из таблицы без перезагрузки.
- Не перезагружаем страницу при сохранении одной заметки.
- Не трогаем фильтры, сортировку, разметку колонок и запись в базу.

## Проверка

- Юнит-тест рендера: форма строки несёт `data-status` с текущим этапом
  (в том числе пустым для новой вакансии).
- Существующие тесты на `back`, редирект без JS и запись этапа остаются
  зелёными.
- Ручная проверка: фильтр по этапу «новая», сменить на «откликнулся» →
  после сохранения страница сама перечитывается, строка уходит из списка.
