# Локальная таблица вакансий

## Что и почему

Сейчас разбор вакансий идёт так: `vacancies export` → xlsx → руками перенести
в гугл-док → отметить этап и комментарий. Выгрузка — снимок, правки в неё не
возвращаются, а этапы приходится потом диктовать Claude в чат. Владельцу нужна
локальная таблица, которая читает `me/job-hunter.db` напрямую: ссылка на
вакансию, вся информация из выгрузки, быстрый этап воронки и одно поле
комментария. Приложение личное, локальное, без логинов и сети наружу.

## Цели

- Открыть одной командой (`vacancies ui`) в браузере и работать без выгрузок.
- Видеть те же данные, что в xlsx: название, компания, оценка, почему, флаги,
  роль, этап, заметка, когда найдена.
- Перейти в вакансию на hh одним кликом по названию.
- Поставить этап воронки и написать комментарий, сохранить кнопкой — запись
  уходит в базу тем же путём, что `vacancies status`.
- Найти нужное среди ~590 строк: фильтры по периоду, оценке, этапу и поиск,
  сортировка по оценке и дате.

## Не-цели

- Не редактируем текст вакансии, вердикт «да/нет/может», профиль и критерии.
- Не отправляем отклики и ничего не делаем на hh.
- Не добавляем пользователей, авторизацию, доступ по сети, мобильную вёрстку.
- Не заменяем `vacancies funnel`, `export` и `sql` — это ещё одно лицо той же
  базы, а не новый источник правды.
- Не тянем ни одной новой зависимости и не собираем фронтенд.

## Анти-цели

- Каждое сохранение перезагружает страницу и сбрасывает место — так работать
  с длинной таблицей нельзя (это и выбрало вариант с fetch).
- Таблица-редактор всех полей: правка «почему» или названия руками разошлась бы
  с базой и следующей выгрузкой.

## Подходы

1. **Серверная страница без JS.** `http.server` + формы, POST и редирект назад
   с якорем. Ноль JS, но каждая правка — перезагрузка.
2. **Серверная отрисовка + ~40 строк ванильного JS.** Кнопка «Сохранить» шлёт
   fetch, строка подсвечивает «сохранено», страница не дёргается; без JS та же
   форма уходит обычным POST. **Выбран.**
3. **JSON API + SPA.** Для одного пользователя лишний слой и сборка.

## Решение

### Команда

`vacancies ui [--port 8765] [--no-open]` — поднимает `ThreadingHTTPServer`
только на `127.0.0.1` и открывает браузер. Занятый порт — понятное сообщение
и код 2, без автоподбора. Ctrl+C — остановка. Базы нет — ошибка с подсказкой
`vacancies init`. Схема и `--db` — как у остальных команд.

### Таблица

Колонки, по одной строке на вакансию:

| Колонка | Источник |
|---|---|
| Название (сама ссылка на hh) | `vacancies.name`, `vacancies.url` |
| Компания | `vacancies.company` |
| Оценка | `latest_scores.score` |
| Почему | `latest_scores.why` |
| Флаги | `latest_scores.flags`, JSON → перечисление |
| Роль | первый `hits.role` |
| Этап | `applications.status`, без строки — «новая» |
| Заметка | `applications.note` |
| Найдена | `first_seen_at[:10]` |

Отдельной колонки «Ссылка» нет: ссылкой становится название — так на строку
меньше и кликать удобнее. Оценка подсвечивается относительно порога из
`scoring.threshold` (`me/config.yaml`, по умолчанию 5): порог и выше — зелёным,
3–4 — серым, ниже — приглушённо. Оценки нет — «—».

Данные берутся тем же запросом, что `hunter/export.py:export_rows` — он уже
отдаёт id, url, name, company, first_seen_at, score, why, flags, status, note,
role. Длинные «почему» и «флаги» показываются целиком в подсказке, в строке —
обрезка; вёрстка — на усмотрение реализатора.

### Фильтры и сортировка

Над таблицей: период (всё / 7 / 30 дней), «оценка от» (число), этап (все /
новая / любой из восьми), поиск по названию и компании. Сортировка — по клику
на «Оценка», «Название», «Найдена», повторный клик меняет направление; по
умолчанию свежие сверху, как в выгрузке. Состояние живёт в query string, чтобы
ссылка и редирект без JS возвращали ту же картину.

**Важно:** фильтрация и сортировка — в Python после выборки, а не в SQL.
`lower()` и `LIKE` в SQLite регистронезависимы только для латиницы, поиск
«яндекс» не нашёл бы «Яндекс». 590 строк в памяти — не проблема.

### Этап и заметка

На строку — `select` с восемью этапами и поле заметки, сохранение одной
кнопкой: `Corpus.set_status(id, status, note)`. Ровно тот же путь, что у
`vacancies status`, поэтому смена этапа попадает в `status_history`, а
напоминания `vacancies todo` продолжают работать. Пустая заметка очищает
поле: `COALESCE('', note)` даёт `''`, а не старое значение.

- Строка без этапа показывает «новая» и пустой `select`; если этап не выбран,
  заметку сохранить нельзя — подсказка «сначала выберите этап».
- «Новая» обратно не выбирается: снять этап нельзя и в CLI (строку
  `applications` мы не удаляем). Ошиблись — выберите другой этап.
- Кнопка сохраняет этап и заметку вместе, без автосохранения: владелец просил
  именно кнопку.

### Сохранение

`POST /save` с `id`, `status`, `note` и текущим query string в `back`.

- С JS: `fetch` с `X-Requested-With: fetch`, ответ 204, строка помечается
  «сохранено» на пару секунд, кнопка на время запроса блокируется.
- Без JS: та же форма уходит обычным POST, ответ — 303 на `back#v-<id>`.
- Неизвестный id, неверный статус или пустой статус — 400 с текстом, база не
  меняется. `CorpusError` — 400, а не стектрейс в браузере.
- Соединение с базой открывается на запрос и закрывается: один пользователь,
  блокировки не нужны.

### Файлы

- `hunter/corpus/ui.py` — рендер страницы (HTML+CSS одной строкой-константой,
  `html.escape` для всех данных из базы), фильтры, обработчик, `make_server`.
- `hunter/corpus/cli.py` — `_cmd_ui`, запись в `_COMMANDS`, парсер.
- `tests/test_corpus_ui.py` — новый.
- `hunter/corpus/GUIDE.md`, `README.md` — команда в списке.

## Ограничения, найденные при разборе

- `Corpus.set_status` не трогает заметку при `None` и не пишет историю, если
  этап не сменился, — правка одной заметки напоминания не сдвигает.
- У 590 вакансий в базе 546 оценок, 12 строк воронки и ни одного вердикта:
  таблица должна нормально показывать и «без оценки», и «новая».
- База живёт в `me/`, который в `.gitignore`; сервер не должен ничего писать
  вне базы.
- Биндимся на `127.0.0.1`: приложение личное, доступ из сети не нужен.

## Что оставляю на усмотрение реализатора

- Вёрстка: ширины, обрезка «почему»/«флагов», липкая шапка, цвета.
- Нужна ли строка «показано N из M» и где именно.
- Поведение при занятом порте: какой текст и предлагать ли `--port`.

## Как проверим

1. `uv run pytest` — тесты страницы и сохранения: HTML-экранирование,
   фильтры (включая поиск по-русски в другом регистре), сортировка, запись
   этапа и заметки, очистка заметки, 400 на неверный статус, редирект без JS.
2. `vacancies ui` — таблица открылась, название ведёт на hh, фильтры и
   сортировка работают.
3. Поставить этап и заметку в браузере → `vacancies funnel` и
   `vacancies show ID` показывают то же; `vacancies todo` видит напоминания.
4. Отключить JS в браузере и повторить сохранение — работает через POST.
