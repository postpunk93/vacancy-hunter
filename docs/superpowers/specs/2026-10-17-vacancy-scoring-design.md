# Оценка вакансий Claude (Sonnet) — дизайн

Дата: 2026-10-17
Статус: на ревью у владельца

## Зачем

Владелец запускает `hunter` раз в день, открывает свежий xlsx и читает
вакансии подряд, открывая каждую ссылку. Много времени уходит на мусор.
Нужна предварительная оценка, которая видна прямо в xlsx. По ней сразу
понятно, что открывать, а что нет. Кроме того, Телеграм должен присылать
только стоящие вакансии.

Оценка учитывает две вещи:
1. **Насколько вакансия подходит владельцу.** Критерии берутся из
   `~/projects/personal/job-search/portrait.md`: роли, признаки «да/нет»,
   удалёнка, деньги.
2. **Конфликтогенный потенциал** глазами конфликтолога: что в тексте
   вакансии обещает будущие конфликты с работодателем.

Критерии будут уточняться итеративно. Поэтому они живут в markdown-файлах
папки поиска, а не в коде: чтобы поменять поведение, достаточно поправить
текст.

## Цели

- Каждая новая вакансия прохода получает от Sonnet итоговую оценку 1–10
  (выше — лучше), одну фразу «почему» и список сработавших флагов
  конфликтности.
- В xlsx, как и сейчас, попадают **все** новые вакансии. Добавляются
  колонки «Оценка», «Почему», «Флаги».
- В Телеграм попадают только вакансии с оценкой **5+** (порог задаётся
  в конфиге) и вакансии, которые оценить не удалось.
- Оценка строится по **полному тексту** вакансии, а не только по карточке
  из выдачи.

## Не цели

- Скорость. Проход может идти долго: паузы между запросами к hh важнее
  времени.
- Строгий фильтр. Конфликтность должна отсекать **только явную дичь**,
  а не всё подряд.
- Вердикты в корпусе (`vacancies mark`) и интеграция с `vacancies.db`.
  Оценка бота и вердикты владельца — разные вещи.
- Интерфейс для правки оценок. Владелец пишет несогласие в «Комментарий»
  xlsx, критерии уточняются правкой md-файлов.

## Анти-цели (провал, даже если всё работает)

- Хорошая вакансия молча пропала: не пришла в Телеграм и не попала в xlsx.
  Любой сбой (не скачался текст, Claude упал, ответ кривой) ведёт
  к пропуску оценки, а не к пропуску вакансии.
- Фильтр режет почти всё из-за мелких признаков (московское время,
  широкая вилка): владелец перестанет ему доверять.
- Блокировка hh из-за частых запросов полного текста.

## Решения владельца

- Полный текст качаем для каждой новой вакансии. Скорость не важна,
  паузы между запросами — «безопасные».
- Критерии соответствия берутся из `portrait.md`.
- Признаки конфликтности — список, который владелец составил с Claude
  (ниже). Брать все не обязательно: отсеивать нужно самую дичь.
- xlsx: все вакансии плюс оценка. Телеграм: только 5+.
- Одна итоговая цифра. Конфликтность работает только как тормоз:
  мелкие признаки цифру не трогают, явная комбинация роняет её ниже 5.
- Модель — Sonnet через Claude Code (`claude -p`), как в media-scan.

## Как это работает

### Место в проходе

Нынешний проход в `hunter/run.py:run_pass`: сбор → очистка и дедуп →
`store.unseen` → `fresh` → дайджест → отправка → `mark_seen` → xlsx.

Новый шаг встаёт между `fresh` и рендером дайджеста:

1. Для каждой вакансии из `fresh` скачать страницу `hh.ru/vacancy/<id>`
   (у zarplata те же id, см. корпус) и достать описание и ключевые навыки.
   Для разбора переиспользовать `hunter/corpus/extract.py:parse_detail`.
2. Отправить вакансии в Claude пачками и получить оценки.
3. Разделить `fresh`:
   - в дайджест — оценка ≥ порога, **или** оценки нет, **или** оценка
     поставлена только по карточке (текст не скачался). По карточке
     слабое название легко уронит хорошую вакансию ниже порога, поэтому
     фильтр на такие оценки не действует (моё решение по итогам ревью);
   - в xlsx — все, в прежнем порядке групп, с новыми колонками.
4. `mark_seen` после успешной отправки — для **всех** вакансий `fresh`,
   включая те, что ниже порога (`sent=False` для них). Иначе они
   вернутся в следующий проход.

Если после фильтра дайджест пуст, а вакансии ниже порога есть,
в Телеграм всё равно уходит короткое сообщение со счётчиком
(см. «Телеграм»). Тогда xlsx пишется так же, как сейчас: после
успешной отправки.

### Полный текст

- Пауза между запросами страниц вакансий — несколько секунд со случайным
  разбросом. Ориентир — 3–6 с: 100 вакансий займут около 8 минут.
  Точные числа на выбор строителя, вынести в константы или конфиг.
- `Blocked` или `Captcha` → прекратить скачивание. То, что успели скачать,
  оценивается по полному тексту. Остальное оценивается по карточке
  и проходит в Телеграм независимо от оценки (см. выше). В дайджест
  добавляется предупреждение ⚠️. Код выхода — как при успешном проходе:
  сбор уже прошёл, вакансии не теряются.
- `NotFound` (вакансию уже удалили) → вакансия идёт без текста, как
  обычная неудача.
- Прочие `FetchError`/`ParseError` по одной вакансии не ломают остальные.

### Оценка через Claude

По образцу `media-scan/backend/src/Scoring/ClaudeCli.php`:

```
claude -p --model sonnet --tools "" --strict-mcp-config --setting-sources "" \
  --no-session-persistence --system-prompt <промпт> \
  --output-format json --json-schema <схема>
```

Вакансии подаются в stdin как JSON. Результат читается из
`structured_output`. `--bare` не используется: в нём работает только
API-ключ, а владелец входит по подписке. Вызов идёт через `subprocess`
с таймаутом. Одна повторная попытка на пачку, как в media-scan.

**Системный промпт** собирается при каждом запуске:
- роль и задача: «ты оцениваешь вакансии для конкретного человека,
  в том числе глазами конфликтолога»;
- содержимое `portrait.md` целиком;
- содержимое `conflict.md` целиком;
- шкала и правило сведения (ниже);
- формат ответа.

**Вход по вакансии:** id (ключ `source:id`), название, компания, зарплата
(как в дайджесте), формат работы, опыт, описание (markdown, урезанное
до разумного предела, например 6000 символов), ключевые навыки.

**Выход по вакансии** (JSON-схема):
- `id` — ключ `source:id` строкой;
- `score` — целое 1–10;
- `why` — одна короткая фраза по-русски;
- `flags` — список коротких названий сработавших признаков конфликтности,
  может быть пустым.

Ответ проверяется как в `Scorer::parseScores`: только id из пачки,
без дублей, оценка обрезается в 1–10, пустое `why` отбрасывается.
Вакансия, по которой нет валидной строки, считается неоценённой.

**Шкала и сведение** (формулировку для промпта уточнит строитель,
смысл такой):
- Основа — соответствие портрету. Подходит под «да» одной из ролей — 7–10;
  «может быть» — 5–6; признаки «нет» или вне рамок (не удалёнка, деньги
  ниже порога, чужая роль) — 1–4.
- Конфликтность — только понижение. Один-два отдельных мягких признака
  (широкая вилка, московский часовой пояс, «и другие задачи») оценку
  **не меняют**, но попадают во `flags`. Явная комбинация тяжёлых признаков
  роняет оценку ниже 5 даже у подходящей вакансии. Явная комбинация —
  **три и больше тяжёлых признака**. Это взято из «быстрого фильтра»
  владельца (приложение A): три признака из пп. 1, 2, 5 и 6. Один-два
  тяжёлых признака могут снизить оценку на балл-два, но не ниже порога
  сами по себе. Решение моё, владелец поправит `conflict.md`.
- Нехватка информации (короткое описание, нет зарплаты) — не повод
  снижать оценку.

### Файлы критериев

Оба лежат в `~/projects/personal/job-search/`, пути — в конфиге.

- `portrait.md` — существует, не трогаем. Владелец будет его дописывать.
- `conflict.md` — **новый**, создаётся в рамках этой работы. Основа —
  список владельца (приложение A), разбитый на две части:
  - **тяжёлые** — то, что в сочетании роняет оценку: нет критериев
    приёмки; ответственность без полномочий; деньги не определены
    по-настоящему: «обсуждается», доход в основном от KPI без формулы
    (одна широкая вилка — это мягкий признак);
    ГПХ/самозанятость/ИП при полной занятости (особенно с риторикой
    «партнёр»); идеология вместо условий; контроль при низком доверии;
  - **мягкие** — только во `flags`, на цифру не влияют: один человек
    вместо команды; несколько заказчиков без арбитра; широкая вилка
    или «от» без верхней границы; непрофильный
    заказчик со сложной технической задачей; задевается эго руководителя;
    часовой пояс.
  Плюс абзац «что снижает конфликтность» и правило сведения обычным
  текстом. Разбиение на тяжёлые и мягкие — моё решение (Claude), владелец
  поправит файл.

Если файл не найден, это ошибка конфига: код 2 при старте, до сбора.

### Конфиг

Новая секция в `config.yaml` (и `config.example.yaml`):

```yaml
scoring:
  enabled: true
  portrait: ~/projects/personal/job-search/portrait.md
  conflict: ~/projects/personal/job-search/conflict.md
  threshold: 5        # в Телеграм — оценка не ниже
  model: sonnet
```

Секции нет или `enabled: false` → бот работает как сейчас: без скачивания
текста, без оценки, все в Телеграм, в xlsx колонки оценки пустые.
Это сохраняет старые конфиги и тесты.

### Флаги командной строки

- `--no-score` — пропустить скачивание текста и оценку в этом запуске.
  Это моё решение: пригодится, если Claude недоступен или нужен быстрый
  проход.
- `--dry-run` **оценивает** вакансии, раз именно так удобно проверять
  правки критериев. В консоль печатается дайджест и отдельно список
  отсеянных: оценка, название, «почему». Вакансии виденными не
  помечаются, xlsx не пишется. Кеши текстов и оценок (см. «Хранение»)
  dry-run читает и пополняет: иначе каждая проверка правки критериев
  заново качает ~100 страниц с hh. Это моё решение; README обновить:
  «dry-run не трогает, что уже присылали, но запоминает скачанные
  тексты».

### xlsx

Колонки: Ссылка, Название, **Оценка**, **Почему**, **Флаги**, Запрос,
Статус, Комментарий. Оценку я ставлю рядом с названием, чтобы видеть
её при чтении сверху вниз (моё решение). У неоценённой вакансии в «Оценка»
пусто, в «Почему» — причина: «текст не скачался», «Claude не ответил».
Флаги перечисляются через запятую. Порядок строк — как сейчас (группы
запросов), внутри группы по убыванию оценки. Автофильтр уже есть, по
оценке можно сортировать в Excel. Выпадающий список статусов переезжает
в свою новую колонку.

### Телеграм

- Строка вакансии начинается с оценки: `• 8 · Название…`, у неоценённой —
  `• ? · …`. Вторая строка — как сейчас.
- Внутри группы запроса — по убыванию оценки, неоценённые в конце.
  Группа, в которой не осталось вакансий, не выводится.
- В шапке после счётчика: «ещё N ниже 5 — в xlsx». Если все ниже порога,
  приходит только шапка, чтобы владелец знал, что проход был и xlsx
  появился.
- Предупреждения ⚠️: блокировка при скачивании текстов; «не оценено N
  вакансий: <последняя ошибка>», если оценка упала хотя бы частично.

### Хранение

Два кеша в `state.db`, чтобы повторный запуск (после сбоя Телеграма
или при проверке критериев через dry-run) не тратил заново запросы
к hh и токены:

- `texts` (key, description, key_skills, fetched_at): скачанные
  полные тексты;
- `scores` (key, criteria_hash, score, why, flags, scored_at).
  `criteria_hash` — хеш содержимого `portrait.md` и `conflict.md`
  вместе с версией промпта. После правки критериев старые оценки
  не используются, вакансии переоцениваются по кешированному тексту
  без обращений к hh.

Неоценённые и оценённые только по карточке в `scores` не пишутся
и в следующий раз пробуются снова. Оба кеша чистятся вместе с `seen`
по тому же сроку в 90 дней. Это моё решение.

### Коды выхода

Без новых кодов. Сбой оценки или скачивания текста не меняет код:
вакансии всё равно доставлены, сбой виден в дайджесте и в логе.

## Ограничения

- Python, uv, существующие модули. Новые зависимости не нужны.
- `run_pass` по-прежнему получает всё внешнее аргументами: скачивание
  страницы вакансии, вызов Claude, паузу. Тесты гоняются без сети
  и без Claude.
- Claude Code (`claude`) установлен на хосте (WSL), вход по подписке.
- Ограничения hh из корпуса: при 403/капче не повторять.
- README: шпаргалка и раздел про оценку, в том числе где править
  критерии. Бэклог — если что-то откладывается.

## Оставлено строителю

- Размер пачки (ориентир — 10 вакансий с полным текстом), таймаут вызова,
  предел длины описания.
- Точная пауза и разброс между запросами страниц вакансий.
- Как помечать оценку по карточке. Пусть в xlsx в «Почему» стоит
  «по карточке, текст не скачался: …», а в Телеграме у оценки звёздочка
  или похожая метка.
- Точная формулировка промпта и шкалы в нём.
- Где жить коду: предлагаю модуль `hunter/scoring.py` (клиент Claude,
  промпт, разбор ответа) и скачивание текстов в `run.py` или отдельном
  модуле.
