# zarplata ищет по своему адресу выдачи

## Что и почему

В `hunter/sources.py` у zarplata стоит путь `/vacancies`. Это не поиск:
страница отдаёт одну-две карточки не по теме запроса, поэтому источник
в проходе почти ничего не добавляет (бэклог, пункт 1). Настоящая выдача
zarplata живёт на `/search/vacancy` — том же движке, что у hh: та же
`HH-Lux-InitialState`, те же имена параметров, те же `vacancyId`.

Проверено вживую 2026-11-10 по запросу «редактор», `area=113`:

| Адрес | Карточек на странице | Всего |
|---|---|---|
| `/search/vacancy` | 50 | 382 |
| `/vacancies` | 0–2 случайные | — |
| hh, тот же запрос | 53 | 2771 |

Пересечение с hh на первой странице — 3 из 50 по id и 3 из 50 по
«компания + название», но это не разные пулы: id у обоих сайтов общие.
Проверено на пяти карточках zarplata — `https://hh.ru/vacancy/<id>`
открывает ту же вакансию с тем же названием и полным текстом (например,
139289794 «Инженер по тестированию робототехнических систем»), так что
страница вакансии и оценка работают без отдельного парсера.

## Как

- `Source("zarplata", ...)` получает `search_path = "/search/vacancy"`.
- Фикстура `tests/fixtures/zarplata_search_python.html` заменяется свежей
  страницей с `/search/vacancy` (50 карточек, `text=python`, `area=113`,
  `search_period=7`) — старая снята с ошибочного адреса и содержит одну
  карточку.
- `test_zarplata_url_uses_its_own_path_but_the_same_parameters` ждёт новый
  путь. Добавляется проверка, что фикстура zarplata разбирается больше
  чем в одну карточку: ровно по этому признаку баг и проявлялся.
- Тест «нет вилки в зарплате» переезжает на новую фикстуру (в ней 36
  карточек без компенсации из 50).

## Не-цели

- Не добавляем новые площадки и не трогаем `vacancies collect` (он пока
  собирает только с hh) — это отдельные задачи.
- Не меняем дедуп, дайджест и схему базы.
- Не разбираемся с пагинацией zarplata: `collect`/`run` останавливаются,
  когда страница короче 50 карточек, а `search_period` у обоих источников
  понимает один и тот же движок.

## Проверка

- Юнит-тесты: `uv run pytest` — зелёные.
- Живой проход без записи в базу и без оценки: `hunter --days 1 --dry-run
  --no-score` — код выхода 0, предупреждений 0, zarplata отдаёт карточки
  по семи запросам из восьми.

## Что показал живой проход

Путь починен, но новых вакансий zarplata не даёт, и причина теперь известна:
её выдача — это те же вакансии hh с теми же id. В проходе от 2026-11-10
zarplata собрала 84 карточки по восьми запросам, и ни одна не дошла до
сводки: `dedupe` схлопнул их по паре «компания + название». В контрольном
прогоне по тем же запросам поглощено 17 карточек zarplata из 17 и только
одна карточка hh. Первый проход дедупа (по `vacancy.key`) их не ловит,
потому что ключ содержит префикс источника: `zarplata:139289794` и
`hh:139289794` — одна вакансия, но разные строки.

Вывод для следующих задач: рычаг «больше вакансий» — не zarplata, а
площадки с собственным пулом (superjob, rabota.ru) и более широкие запросы.
Отдельный вопрос — не ставить ли префикс источника в ключ для hh/zarplata,
раз id общие; это уже про дедуп корпуса, а не про адрес выдачи.
