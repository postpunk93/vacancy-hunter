Открытые вопросы по job-hunter. Ни один не блокирует работу бота —
это решения, которые лучше принимать, пожив с ботом пару недель.

Два прежних пункта — частота предупреждений о сломанном парсере и потолок
в 30 вакансий — сняты 2026-10-13: при ручном запуске нет ни кулдауна, ни потолка.

## 1. zarplata отдаёт одну карточку на запрос

**Что сейчас.** Выдача zarplata.ru для анонимного клиента вживую
(2026-10-02) содержит 1 вакансию там, где hh по тому же запросу отдаёт 50.
Фикстура `zarplata_search_python.html` тоже с одной карточкой.

**Почему важно.** Источник `zarplata` в боте почти ничего не добавляет,
но тратит запросы. При этом id вакансий zarplata совпадают с hh
(кросспостинг), так что дубли и так схлопываются.

**Что можно сделать.** Выяснить, отдаёт ли zarplata больше при другом
`items_on_page`/пагинации; если нет — убрать zarplata из `sources`
по умолчанию.

**Где менять:** `hunter/sources.py`, `config.example.yaml`.

## 2. Публикация на GitHub как витрины

**Когда.** Перед первыми откликами, где в резюме будет ссылка на проект.

**Что сейчас (2026-10-17).** Личное из файлов убрано: признаки
конфликтности, город, пути, id откликов. `master` — один чистый коммит.
Полная история лежит в локальной ветке `archive/full-history`, её не
пушить. Старый приватный `postpunk93/vacancy-hunter` остаётся архивом.

**Что сделать.**
1. Перед публикацией ещё раз проверить, что в отслеживаемых файлах нет личного:
   тест `test_no_personal_paths_in_public_files` и `git grep` по городу,
   домашнему каталогу, почте и id откликов.
2. Создать публичный `postpunk93/job-hunter` и запушить `master`
   (`gh repo create job-hunter --public --source . --remote origin --push`,
   старый remote заранее переименовать в `old-origin`).
3. Вписать ссылку на репозиторий в README (сейчас на месте ссылки заглушка
   в строке `git clone`).
4. Переименовать папку в `~/projects/personal/job-hunter`, затем
   `uv tool install --editable . --reinstall`. Без переустановки хук
   начала разговора молчит.

**Где менять:** `README.md`, настройки GitHub.

## Что уже рассмотрено и сознательно оставлено как есть

Чтобы не возвращаться к этому по второму кругу. Финальное ревью всей
ветки разобрало каждый пункт и признал текущее поведение приемлемым:

- `_QUERY_FIELDS` в `hunter/config.py` перечисляет поля руками, а не
  выводит их из `dataclasses.fields(SearchQuery)`. Расхождение всё равно
  даёт понятную ошибку при старте.
- Пробельные значения `name` и `text` в конфиге проходят проверку.
  Конфиг пишет владелец руками.
- `sources: hh` строкой вместо списка превращается в `('h','h')`.
  Падает при старте с кодом 2 и сообщением, где перечислены допустимые
  источники, — непонятно, но не опасно.
- `_split_oversized` в `hunter/digest.py` обрезает строку длиннее 4096
  символов. Строка вакансии — около 200 символов; недостижимо.
- `parse_args()` вызывается до `_use_utf8_console()`. Вывод argparse
  состоит из кириллицы, которую cp1251 кодирует без ошибок.
- `Store.is_empty()` и таблица `meta` в `run.py` больше не используются:
  с переходом на ручной запуск (2026-10-13) ушли особый первый запуск,
  признак жизни и кулдаун предупреждений. Оставлены — покрыты тестами,
  старые базы открываются без миграций.
