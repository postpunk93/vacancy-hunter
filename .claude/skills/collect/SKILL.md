# Сбор и оценка

1. **Проход.** `hunter`. После перерыва в несколько дней — `hunter --days N`
   (N — дней с прошлого сбора, до 30). Проход долгий: тексты качаются,
   Claude оценивает пачками — запускай в фоне и дождись конца.

2. **Код выхода.**
   - 0 — читай сводку.
   - 2 — нет `me/config.yaml` или он кривой: скажи владельцу, что
     сломалось; если настройки нет — предложи `setup`.
   - 3 — блокировка или капча hh. Остановись, скажи владельцу,
     не повторяй. Повтор — только по его команде и не раньше чем через час.
   - 1 или 4 — перескажи ошибку из вывода.

3. **Сводка владельцу.** Коротко, в чате:
   - три числа: сколько новых прошло порог, сколько рядом (3–4) и сколько
     осталось без оценки;
   - лучшие — нумерованным списком: номер, оценка, название, компания,
     деньги, id и одна фраза почему. Номера нужны, чтобы владелец ответил
     «черновики по 2, 5, 7»;
   - предупреждения из вывода (не нашлась выдача, не скачался текст,
     Claude не оценил) — одной строкой каждое.
   Рядом одной строкой не перечисляй, если не просят. Если новых нет — так и скажи.

   «Покажи рядом» — полный серый список из базы: `vacancies sql` по примеру
   «Рядом с порогом» из справочника, нумерованным списком.

4. **Дальше** решает владелец: черновики (`apply`), донастройка (`tune`)
   или пропустить. Вердикты и статусы сам не ставь.

Нужен список лучших из базы, а не из прохода («покажи лучшие за неделю») —
`vacancies sql` по примеру «Лучшие свежие оценки» из справочника.
Выгрузка в xlsx — `vacancies export`, только по просьбе.
