# job-hunter

Поиск работы на hh.ru от первого разговора до тестового задания, целиком
в диалоге с Claude Code. Владелец открывает Claude в папке проекта
и говорит обычными словами: «давай настроим», «собери свежие»,
«черновики по 2, 5, 7», «слишком много маркетинга». Claude сам вызывает
нужные команды, оценивает вакансии, пишет черновики и следит за воронкой.
Отклик отправляет владелец — сам.

## Весь путь

| Шаг | Владелец говорит | Что делает ИИ | Где |
|---|---|---|---|
| 1. Опрос | «давай настроим» (или первый запуск) | Расспрашивает об опыте, ролях, деньгах, формате; разбирает 5–10 вакансий «нравится» и 3–5 «похоже, но нет», записывает вердикты его словами | [`setup`](.claude/skills/setup/SKILL.md) |
| 2. Критерии | — | Собирает `me/profile.md`: кто я, что ищу (роли с признаками «да» и «нет»), красные флаги. Этот файл и есть промпт оценки. Пишет поисковые запросы hh, резюме под каждую роль и стратегию | [`setup`](.claude/skills/setup/SKILL.md), [`templates/`](templates/) |
| 3. Сбор и оценка | «собери свежие» | Запускает проход: выдача hh и zarplata, отсев рекламы и дублей, скачивание текстов, оценка каждой вакансии 1–10 с причиной и флагами. В чат — нумерованный список прошедших порог | [`collect`](.claude/skills/collect/SKILL.md), [`hunter/run.py`](hunter/run.py), [`hunter/scoring.py`](hunter/scoring.py) |
| 4. Донастройка | «слишком много X», «подними порог» | Правит профиль или конфиг, пересчитывает оценки по уже скачанным текстам без запросов к hh, говорит, что поднялось и что упало | [`tune`](.claude/skills/tune/SKILL.md), [`hunter/evaluate.py`](hunter/evaluate.py) |
| 5. Черновики | «черновики по 2, 5, 7» | Выбирает резюме, пишет сопроводительное письмо по фактам из резюме, отвечает на вопросы работодателя, отмечает тестовое со сроком | [`apply`](.claude/skills/apply/SKILL.md) |
| 6. Воронка и тестовое | «откликнулся», «позвали», «отказ» | Ведёт этапы отклика. В начале каждого разговора напоминает: тестовое со сроком, черновик без отклика, отклик без ответа | [`.claude/settings.json`](.claude/settings.json), [`hunter/corpus/funnel.py`](hunter/corpus/funnel.py) |

Как Claude узнаёт, что делать: [`CLAUDE.md`](CLAUDE.md) — этапы и правила,
skills в [`.claude/skills/`](.claude/skills/) — пошаговые инструкции на каждый
этап, [`hunter/corpus/GUIDE.md`](hunter/corpus/GUIDE.md) — справочник команд
и схемы базы.

Правила, которые Claude не нарушает: вердикт «подходит / нет» ставит только
владелец; отклик не отправляется автоматически; при блокировке или капче hh
Claude останавливается и не повторяет запрос.

## Как это работает на деле

Цифры с базы владельца за две недели поиска, до перехода на эту версию:

- собрано **467** вакансий по 6 ролям;
- полный текст есть у **98**, у остальных 369 — только карточка из выдачи;
- владелец поставил вердикт **84** вакансиям: 35 «да», 44 «нет», 5 «может быть».

На этих вердиктах проверена оценка по профилю
(`vacancies eval`, [`hunter/evaluate.py`](hunter/evaluate.py)): из 79 вакансий
с ответом «да» или «нет» оценка Claude совпала с решением владельца
в **70 случаях (89%)** при пороге 5. Средняя оценка — 7,4 у «да» и 3,0 у «нет».

## Установка

Нужны [uv](https://docs.astral.sh/uv/) и [Claude Code](https://claude.com/claude-code),
залогиненный по подписке: оценка вакансий идёт через него.

```bash
git clone <ссылка на репозиторий> job-hunter
cd job-hunter
uv sync --extra dev
uv tool install --editable .   # команды hunter и vacancies — в PATH
claude                         # открыть Claude Code в папке проекта
```

`uv tool install --editable .` обязателен: хук начала разговора вызывает
`vacancies todo`, а Claude — `hunter` и `vacancies`, и они должны быть в PATH.
После смены зависимостей — то же с `--reinstall`.

При первом открытии `me/profile.md` ещё нет, и Claude сам начинает опрос
по `setup`. Всё личное — профиль, резюме, конфиг, база, черновики — лежит
в `me/`, а она целиком в `.gitignore`.

## Шпаргалка команд

Обычно их вызывает Claude, но всё работает и руками.

```bash
hunter                    # проход: собрать, скачать тексты, оценить, сводка
hunter --days 7           # за неделю — после перерыва (1–30)
hunter --dry-run          # ничего не помечать виденным и не слать
hunter --no-score         # без текстов и оценки

vacancies init            # создать me/ и базу
vacancies collect --role R --text "запрос hh"   # карточки из выдачи под роль
vacancies fetch ID|URL …  # полный текст
vacancies show ID …       # вакансия в Markdown
vacancies mark ID yes|no|maybe "почему"         # вердикт владельца
vacancies status ID applied                     # этап воронки
vacancies funnel          # отклики по этапам
vacancies todo            # о чём напомнить
vacancies sql "SELECT …"  # запрос к базе на чтение
vacancies rescore         # пересчитать оценки после правки профиля, без сети
vacancies eval --from старая.db                 # сверить оценку с вердиктами
vacancies export          # xlsx — только по просьбе
```

Подробно — в [`hunter/corpus/GUIDE.md`](hunter/corpus/GUIDE.md).

## Коды выхода `hunter`

| Код | Значение |
|---|---|
| 0 | Проход завершён |
| 1 | Телеграм не принял сообщение; вакансии остались непрочитанными и придут в следующий раз |
| 2 | Нет `me/config.yaml` или ошибка в нём, в `.env` или в `--days` |
| 3 | Все источники заблокировали запросы — подождите час |
| 4 | Непредвиденная ошибка; подробности — в `me/logs/hunter.log` |

## Телеграм — по желанию

По умолчанию сводка прохода печатается в консоль, и Claude пересказывает её
в чате. Чтобы она приходила ещё и в Телеграм, добавьте в `me/config.yaml`
строку `telegram: true` и создайте `me/.env`:

```
TG_BOT_TOKEN=токен от @BotFather
TG_CHAT_ID=ваш chat_id
```

## Как устроен сбор

Поисковый API hh и zarplata отдаёт 403 анонимным запросам, поэтому данные
берутся из публичной выдачи: в HTML страницы встроен JSON со всем состоянием
поиска ([`hunter/parse.py`](hunter/parse.py)). Тексты и оценки кешируются
в базе: повторный проход их не качает и подписку не тратит. При смене вёрстки
проблемная страница сохраняется в `me/debug/`, а `tests/test_parse.py`
покажет, когда парсер снова в порядке.

Отложенные решения — в [`docs/backlog.md`](docs/backlog.md).
